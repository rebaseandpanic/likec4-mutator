# Test plan: CLI parity with `apply`, semantic validation like `likec4 validate`, `.likec4` / `.like-c4` in the CLI

**Date** 2026-10-23 · **Version** v3 (after spec/plan repair D161–D165) · **Requirements**: `docs/plan/lc4m-15.31/spec.md` · **Plan**: `docs/plan/lc4m-15.31/plan.md` (build order T001 → T002 → T004 → T003 …) · **Task**: lc4m-15.31 (with lc4m-28)

Levels: the project provides **unit** only (vitest; library and CLI on LikeC4's real parser; CLI through the in-process program builder of T003 or `npx tsx src/cli.ts` subprocesses) plus the coverage check in `npm run lint`. No integration / e2e / smoke / artifact-contract rows exist or are created. Every row is `wave`.

Shared conventions of the rows below:
- "equals `apply`" = the same model is copied twice; one copy gets the command, the other `apply` with that single mutation (same fields as JSON); files compared byte for byte. `apply` is the reference the spec names (US-1 acceptance); the independent check is `expectValidLikeC4` (oracle, `tests/helpers/likec4-model.ts`).
- "library value" = the method called directly on `LikeC4Mutator.fromFiles` of the same files with the same arguments, never the CLI's own output.
- CLI rows run in process through `buildProgram({ stdout, stderr })` (T003) unless the row says "subprocess".
- No message text is asserted except where the spec names it as contract (kept success lines D137, the success line of `validate`, the three extensions in "no files found", the `<flag>` / `<operation>` tokens, `apply`'s detail relation P3).

## Not covered by a row (with reason)

Behaviour without a known input (D164; spec SC-005 note, plan T009/T010 "Untested behaviour"); stated in JSDoc / README / CHANGELOG, not tested. Producing them would need a fault-injection seam, which the plan rejects (P8).
- **Unlocated record of an exception escaping view computation** (US-5, D152; record `origin: 'views'`), its CLI line `message` and its `--json` form (US-6) — stage-4 probes (cyclic `extends`, self `extends`, empty dynamic view, `parallel`, deployment view, nested actors in a sequence view) never made `diagrams()` throw.
- **A rejected `validateModel` call / CLI `Error: <reason>` when the check cannot run** (US-5, US-6) — no input makes the language services fail to build.
- **A difference made by `layout: false` / `--no-layout`** (US-5, US-6) — with no input producing a view-step record, skipping the step changes no result; rows 28–29 only show that language-service records remain.
- **A file failing only on brace balance and accepted by LikeC4 exits 0** (US-6, INV-6 exception 1) — no such file found: the brace check uses LikeC4's own lexer and runs only on files that parse (probes: stray `}`, stray `{`, unclosed block, braces in strings and URIs).
