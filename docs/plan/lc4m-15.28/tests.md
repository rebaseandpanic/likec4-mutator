# Test plan: Read and edit the LikeC4 deployment model

**Date** 2026-10-12 · **Requirements**: `docs/plan/lc4m-15.28/spec.md` · **Plan**: `docs/plan/lc4m-15.28/plan.md`

All product rows are vitest unit tests (`npm test`); the project has no other test level. Every row runs in `wave`. Row numbers from round 1 are kept so the critiques can cross-reference them. Rows 1–5 and 37 moved to "Test infrastructure and review evidence". New rows start at 83.

**Expected values** come from three places:
- LikeC4 1.59.4 itself: `buildLikeC4Model` (`$data` layer and getters), the new `linkedReferences`, and `validateLikeC4` / `expectValidLikeC4`.
- The literal outputs recorded in spikes 02–07.
- The spec text, or the input text of the test itself (positions, declarations).

No expected value comes from the library's own output.

**Conventions used in the rows:**
- **BI (byte-identical):** `serialize()` before equals after, and a read of the addressed entity returns its earlier value (INV-2).
- **W (surviving-entity oracle check):** after every accepted deployment write, every node, instance and deployment relationship still in the workspace is compared field by field with the oracle. The comparison uses `expectDeploymentNodesAgreeWithLikeC4`, `expectDeploymentInstancesAgreeWithLikeC4` and `expectDeploymentRelationshipsAgreeWithLikeC4` (T002), including the D2/D10 exceptions. The output must also pass `expectValidLikeC4` (SC-002, SC-003).
- **2F (both fixtures):** the row runs on `tests/fixtures/deployment-zones/` and on `tests/fixtures/deployment-clusters/` (T001), with the entity names of each fixture.
- **P (presence first):** a row that iterates fixture entities first asserts that the constructs it needs are in the oracle's `$data.deployments` (§6: non-emptiness before the loop).

**Fixture blind spots (apply to every 2F row):**
- Both fixtures are valid, LF-only, free of syntax errors, duplicate ids and ambiguous names, and use the default project (no `likec4.config.json`).
- The library parses each file standalone with `LangiumParser` (no linking), while the oracle links. A reference form that is absent from the fixtures is not exercised by them.
- Invalid, CRLF and ambiguous cases therefore live inline in the rows that need them (18, 42, 50–51, 57–58, 62–63, 68, 70, 87–92).
